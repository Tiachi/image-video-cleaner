# 三阶段合同、Prompt和统计

日期：2026-10-23。范围固定为图片/视频画面QA。没有指定真实输入，本仓库提供可配置实现，不能把实现/测试状态写成已清洗某个百万数据集。

## 输入与逐步交接

一条JSON对象占一行，支持两种明确的QA结构：`conversations`交替human/gpt（或user/assistant）的from/value（或role/content）；或者顶层字符串question/answer。媒体支持images/videos列表及image_path/video_path单路径别名，冲突则待复核。相对路径按media_root解析，绝对路径必须在allowed_media_roots内；拒绝URL、目录穿越和越界软链。额外原始字段原样保留但不探测。

原始JSONL不可变 → Stage01正式accepted → Stage02正式accepted → Stage03。每次交接读取父回执/identity/summary及SHA绑定的audit，逐行核验raw_sha256、原始行号和QA数。先前剔除/待复核不自动恢复，pilot不是正式父输入。

所有阶段保留原始行字节；多QA任一明确剔除则整行剔除，否则有待复核则整行待复核。输出不是直接修改问题/答案的工具，不自动拆轮、不改答案、不生成推理、不执行训练格式转换。

## 第一阶段：机械规则

| 检查 | 默认策略 |
|---|---|
| 媒体不存在/零字节 | 剔除 |
| IO错误、解码/结构不支持 | 待复核 |
| 空问题/答案 | 移除图片/视频占位符、空白/不可见格式字符后判断；空则剔除 |
| n-gram循环复读 | 中日韩汉字按字、英文按词；4-gram，至少32 token，重复比例≥0.6，默认待复核 |
| 精确重复 | 完全相同媒体/切片、QA和其余上下文（不含顶层ID）保留首次；不同媒体同问题模板不当重复 |
| 清晰度 | FFmpeg blurdetect；图片原生第一帧、视频实际切片8帧均值；越大越模糊 |

模糊阈值默认null，必须看真实样本校准后设置，否则清晰度未定的行不会进入通过集。不是按像素分辨率直接判清晰，也不是跨数据集的通用模糊分界。n-gram是单条文本内部循环重复，不声称全池近重复去重。

## 第二阶段：纯文本模型合同

模型只看当前问答、此前对话和明确同题的cot/reasoning_process/rationale字段，不看画面、媒体路径、原ID、第一步分数或未来轮答案。完整Prompt见[纯文本Prompt](../prompts/text_qa_quality_v1.txt)。

固定输出：`质量分,QA匹配,拒答类型,明显错误,CoT类别,语言`。

| 字段 | 含义 |
|---|---|
| 质量分 | 1~10；质量不等于长度，直接事实题可高分 |
| QA匹配 | 0明确不匹配、1匹配、2未定；不是媒体事实正确性 |
| 拒答 | 0正常、1无效拒答、2合理拒答、3未定；不按关键词一刀切 |
| 明显错误 | 0未发现文本可证明错误、1明确核心错误、2未定；不能猜媒体事实 |
| CoT | 用户确认0已有有效CoT、1无且不适合补充、2无且适合补充；未定9转null待复核 |
| 语言 | 1中文、2英文、3其他、4混合、0未知 |

QA明确不匹配、无效拒答、文本明确错误剔除；高分与这些确定坏标签同时出现则标签冲突待复核。未定、协议错误、服务失败、超长输入待复核。minimum_score=null先不按分数筛；设置阈值须用新output。不能将CoT2解释成“可以无证据自动补推理”。

## 第三阶段：视觉模型合同

帧缓存与时长处理见[缓存设计](frame_cache_reference.md)。每行准备帧一次，各QA复用，模型不看第二步的分类结果以免打分锚定；第二步标签原样保存在第三步属性中。

固定输出：`质量分,媒体匹配,证据帧1,证据帧2`，例如`8,1,2,5`。完整Prompt见[带媒体Prompt](../prompts/media_qa_quality_v1.txt)。

| 媒体匹配 | 分流 |
|---|---|
| 0明确视觉矛盾 | 必须引用当前帧，分数≤4；剔除 |
| 1画面证据支持关键答案 | 必须引用当前帧；按显式质量阈值决定 |
| 2证据不足/对应关系不明 | 待复核；低分也不直接当作已经证实的错误 |

证据ID只允许0无证据或1~N实际图片编号，不允许两次引用同一ID充数。未知标签、越界引用或矛盾高分待复核；不猜修复输出。图片序列不保证完整视频、精确时间、计数或因果证据，未采到不能当作不存在。

### Prompt背后的想法

先用规则去掉便宜且确定的坏样本，再做文本语义判断，最后才用视觉模型验关键事实，减少昂贵推理。CoT三类只决定是否有/适合，不为了增长答案造解释。第三步把画面证据与文本流畅度分开打分，并保留帧时间戳供人复查。六数字/四数字输出把JSON生成与统计留给程序。Prompt和解析约束只能提高一致性，不等于正确率保证，仍需真实抽验。

## 中间产物与口径

每阶段的accepted/rejected/review是分流数据；audit包含全部输入行的原因与测量；第二、三步attributes包含全部受审QA标签并带row_status，不能直接全部当通过标签使用。

summary.json/report.md保存输入与三种分流的行/QA数、可重叠原因计数、质量分/匹配/语言/CoT分布（全部合法结果和通过集分开）、模型状态/调用/token。第三步保存缓存帧引用命中/新增观察；跨恢复块统计不是本次新增文件/吞吐。还有父阶段数量、累计通过比例、源与输出SHA、完整代码提交与Prompt身份。

中间part先staging、receipt后原子发布。重跑只复用完整且SHA正确的块；中断块可能重新发请求，当前不对超时做自动模型重试。缓存容量/损坏等基础设施失败会停止，不能把全池剩余样本判坏。规则/Prompt/服务声明/配置变更须新output，禁止混合旧身份。

本地测试覆盖机械规则、缓存/帧边界、分流、继承标签、原文保留与统计守恒。真实清洗量、召回/误删、视觉判断准确率和吞吐仍未知；工具的PASS仅表示本阶段执行成功。
